# 스윗밸런스 신제품 아이디어 발굴

리뷰·매출·트렌드 데이터를 근거로 신제품 콘셉트 후보를 만든다. 숫자 집계와 엑셀 작성은 스크립트가 하고,
콘셉트 발상과 근거 연결은 Claude가 한다. **최종 선택은 상품팀이 한다**는 점을 결과물마다 적는다.

## 원칙 (반드시 지킬 것)

1. **근거 없는 후보는 만들지 않는다.** 모든 콘셉트에는 `analysis.json`에 실제로 있는 리뷰 ID(예: `R0123`)를 1개 이상 연결한다. 스크립트가 ID를 검증하고, 없는 ID를 쓴 후보는 엑셀에서 "근거 확인 필요"로 표시된다.
2. **리뷰는 원문 그대로 인용한다.** 요약하거나 고쳐 쓰지 않는다. 파일명과 행 번호는 스크립트가 자동으로 붙인다.
3. **트렌드는 출처가 있어야 한다.** 트렌드 파일이 없어서 웹 검색으로 보강하면 콘셉트의 `trend_source`에 링크를 적는다. 출처를 못 찾으면 비워 두고 트렌드 점수를 낮게 준다. 지어내지 않는다.
4. 점수는 AI 참고 의견이다. 사람과 AI는 고르는 기준이 다를 수 있으므로(예: AI가 가격을 과대평가) 엑셀과 보고서 첫머리에 이를 명시한다.

## 입력 폴더 구조

사용자가 연결한 폴더(이하 `DATA`)를 쓴다. 하위 폴더가 없어도 파일명·컬럼으로 구분한다.

```
DATA/
  리뷰/        크롤링한 리뷰 .xlsx/.xls/.csv (여러 개 가능)
  매출/        제품별 매출, 목표, 목표달성률
  트렌드/      키워드, 검색량/언급량 (선택)
  제품마스터.xlsx  제품명, 재료, 가격, kcal, 카테고리 (선택)
```

인식하는 컬럼 이름(일부만 있어도 됨)은 `scripts/analyze_data.py` 맨 위 `COLUMN_ALIASES`에 있다. 혜민님 크롤링 파일 컬럼명이 다르면 그 목록에 추가한다.

## 실행 순서

### 1단계: 데이터 분석

```bash
pip install pandas openpyxl  # 없을 때만
python scripts/analyze_data.py "DATA" --out "DATA/결과"
```

- `DATA/결과/analysis.json`과 `analysis_summary.md`가 생긴다.
- 실행 결과에 **파일별로 어떤 컬럼을 무엇으로 인식했는지** 출력된다. 리뷰 본문 컬럼을 못 찾았거나 엉뚱한 컬럼을 잡았으면, 사용자에게 보여 주고 `COLUMN_ALIASES`를 고친 뒤 다시 돌린다.
- 카테고리를 좁히려면 `--category 샐러드` 처럼 준다(제품명·카테고리 컬럼에 포함된 것만 분석).

### 2단계: 분석 결과 읽기

`analysis_summary.md`를 먼저 읽고, 필요한 부분만 `analysis.json`에서 찾아본다. 주요 항목:

- `products`: 제품별 리뷰 수, 평균 평점, 매출, 목표달성률, 자주 나온 속성
- `attributes`: 맛/식감/양/가격/건강/편의/재료 등 속성별 긍정·부정 언급 수와 대표 리뷰 ID
- `wishes`: "~했으면", "~있으면 좋겠" 같은 바라는 점 리뷰
- `complaints`: 평점 낮은 리뷰
- `keywords`: 리뷰 전체 자주 나온 단어/2어절
- `trends`: 트렌드 키워드와 수치(있을 때)
- `reviews`: `{id, file, row, product, rating, text}` 전체(긴 데이터는 필요한 ID만 찾아 읽는다)

### 3단계: 트렌드 보강 (트렌드 파일이 없거나 빈약할 때만)

웹 검색으로 최근 3개월 식품·간편식 트렌드 키워드 5~10개를 찾고, 키워드마다 출처 링크를 기록한다.
사용자가 웹 검색을 원하지 않으면 건너뛰고 트렌드 점수는 일괄 2점 이하로 둔다.

### 4단계: 콘셉트 후보 만들기

`DATA/결과/concepts.json`을 아래 형식으로 쓴다. 기본 50개, 사용자가 개수를 말하면 따른다.

발상 방법(골고루 섞기):
- **잘 팔리는 제품 확장**: 목표달성률 상위 제품의 공통 속성(재료·식감·가격대·용도) 조합
- **불만 해결**: 부정 언급이 많은 속성을 고친 버전
- **바라는 점 실현**: `wishes`에 나온 요청을 그대로 제품화
- **트렌드 결합**: 트렌드 키워드 × 스윗밸런스 강점(샐러드·저당·고단백·간편식)
- **미충족 상황**: 리뷰에 나온 먹는 상황(출근, 운동 후, 야식, 다이어트 등) 중 맞는 제품이 없는 것

```json
{
  "generated_at": "2026-10-08",
  "notes": "웹 검색 보강 여부 등 메모",
  "concepts": [
    {
      "name": "단호박 크림 고단백 샐러드볼",
      "category": "샐러드",
      "one_liner": "포만감 부족 불만을 단호박·닭가슴살로 해결한 한 끼 볼",
      "target": "점심 대용으로 샐러드를 먹는 20~30대 직장인",
      "key_ingredients": "단호박, 닭가슴살, 퀴노아, 요거트 드레싱",
      "price_range": "8,900~9,900원",
      "approach": "불만 해결",
      "rationale": "양·포만감 부정 언급 다수, 단호박 들어간 제품은 목표달성률 상위",
      "evidence_review_ids": ["R0012", "R0345"],
      "related_products": ["리코타 단호박 샐러드"],
      "trend_keywords": ["고단백"],
      "trend_source": "https://... (웹 검색으로 찾은 경우만)",
      "risks": "단호박 원가 계절 변동, 드레싱 유통기한",
      "scores": {"need": 4, "sales": 4, "trend": 3, "differentiation": 3, "feasibility": 4}
    }
  ]
}
```

점수 기준(각 1~5점):

| 항목 | 가중치 | 5점 | 1점 |
|---|---|---|---|
| need 고객 니즈 | 30% | 근거 리뷰가 많고 같은 요청이 반복됨 | 리뷰 1건뿐 |
| sales 매출 연관성 | 25% | 연결된 제품의 매출·목표달성률이 상위 | 매출 데이터와 연결 없음 |
| trend 트렌드 | 15% | 출처 있는 상승 키워드와 직접 연결 | 트렌드 근거 없음 |
| differentiation 차별성 | 15% | 현재 라인업·시장에 비슷한 제품 없음 | 기존 제품과 거의 같음 |
| feasibility OEM 제조 가능성 | 15% | 기존 OEM 공정(복만사 등)으로 바로 가능 | 새 설비·특수 원료 필요 |

가중치는 `scripts/build_excel.py`의 `WEIGHTS`에서 바꿀 수 있다.

### 5단계: 엑셀 만들기

```bash
python scripts/build_excel.py "DATA/결과/analysis.json" "DATA/결과/concepts.json" --out "DATA/결과"
```

`DATA/결과/신제품_콘셉트후보_YYYYMMDD.xlsx`가 생긴다. 시트 구성:
1. **읽어주세요**: 데이터 범위, 점수 기준, "AI 참고 의견, 최종 선택은 상품팀" 문구
2. **콘셉트 후보**: 총점 순 정렬, 근거 리뷰 원문(파일명·행 번호 포함), 상품팀 검토 칸(채택/보류/제외, 검토자, 메모)
3. **근거 리뷰**: 콘셉트별로 인용된 리뷰 원문 전체
4. **제품별 현황**: 리뷰·매출 요약
5. **속성 분석**: 속성별 긍정/부정 언급
6. **트렌드**: 사용한 트렌드 키워드와 출처

스크립트가 "근거 확인 필요" 경고를 출력하면, 해당 콘셉트의 리뷰 ID를 고치거나 콘셉트를 뺀 뒤 다시 실행한다.

### 6단계: 요약 보고서

팀장님께 공유할 짧은 보고서를 쓴다(Docs 연결돼 있으면 Docs 문서, 아니면 `DATA/결과/요약보고서_YYYYMMDD.md`).

구성:
1. 한 줄 결론 + "AI 참고 의견이며 최종 선택은 상품팀" 문구
2. 분석 데이터 범위(파일 수, 리뷰 수, 기간, 제품 수)
3. 데이터에서 보인 것 3가지(숫자와 함께)
4. 추천 TOP 5: 콘셉트명, 한 줄 설명, 근거 리뷰 원문 1~2개(파일명·행 번호), 관련 매출 수치, 리스크
5. 다음 단계 제안(상품팀 검토 → OEM 파트너 제조 가능성 확인)
6. 트렌드 출처 링크 목록

## 자주 생기는 문제

- **리뷰 본문 컬럼을 못 찾음**: 실행 로그의 컬럼 목록을 보고 `COLUMN_ALIASES["text"]`에 컬럼명 추가
- **제품명이 리뷰와 매출에서 다르게 적힘**(띄어쓰기, 용량 표기 등): 스크립트가 공백·괄호를 지우고 비교한다. 그래도 안 맞으면 `제품마스터.xlsx`에 `별칭` 컬럼(쉼표 구분)을 추가
- **리뷰가 수만 건**: 그대로 돌려도 되지만, 4단계에서 `reviews` 전체를 읽지 말고 `attributes`/`wishes`/`complaints`의 대표 ID 위주로 본다
